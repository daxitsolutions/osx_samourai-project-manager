# Issue #36 — réimport des risques, 2 novembre 2026

## Périmètre et version

[Issue #36](https://github.com/daxitsolutions/osx_samourai-project-manager/issues/36).
Base réellement testée : `5692f66b006353dd924d01490c81c5e3118c6539`, avec les modifications non commitées de `SamouraiStore.swift`, les traductions FR/EN et `RiskImportTests.swift`. La branche a ensuite avancé vers `a4c94d03e98305fa3d0756e96b07fb504c253c76` après intégration de #60/#61 : arbre source identique, seuls les commits de fusion sont ajoutés.

Le réimport fusionne les valeurs renseignées dans le risque existant. Règle explicite : les cellules absentes, vides ou blanches conservent les données locales ; aucune cellule vide ne demande une suppression. L’UUID, la date de création, l’échéance locale et l’historique sont conservés. Les champs miroir (titre, responsable, mitigation et sévérité) sont mis à jour seulement si leur champ importé est renseigné. Les modifications de champs importés ajoutent une entrée automatique avec les anciennes/nouvelles valeurs. La date de modification ne recule pas ; un import identique n’ajoute pas d’historique. La règle de rapprochement existante (identifiant externe et titre normalisés) et le rattachement projet existant sont conservés.

## Environnement et adaptation du banc

macOS 26.6.2, arm64 ; Command Line Tools, Swift 6.4 (`swiftlang-6.4.0.34.1`). Fixtures et persistance exclusivement dans des dossiers temporaires UUID, jamais dans les données utilisateur.

Le banc métier temporaire copie les modèles, stores et services métier du dépôt. Comme dans les rapports #32/#34, seules les parties SwiftUI dépendant d’AppState sont exclues de `AppLocalization.swift` (à partir d’`extension AppState`) et d’`ImportProgressTracker.swift` (à partir de `SamouraiImportProgressSheet`). Un fichier temporaire fournit `Bundle.module = Bundle.main`. Aucun changement dans les imports, la validation, la récupération ou la persistance testés. Le runner appelle `Testing.__swiftPMEntryPoint()` et transmet son code de sortie. Le plugin Testing des Command Line Tools est chargé explicitement ; le framework et sa bibliothèque d’interopérabilité sont indiqués dans les commandes ci-dessous.

Ce banc isolé ne valide ni la compilation de l’application entière, ni la distribution des traductions, ni son interface. Les trois checks CI restent nécessaires avant fusion.
