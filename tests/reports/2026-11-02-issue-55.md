# Validation de l'issue #55 — 2 novembre 2026

## Périmètre

[Issue #55](https://github.com/daxitsolutions/osx_samourai-project-manager/issues/55) : déporter la lecture et l'analyse Merlin hors du thread UI.

Base : `e99e2e6` (`main`). Commit de code testé : `c7a87233d1497fdedf556a5637de4dafa8e08120` (branche `codex/fix-55-merlin-off-main`).

Changements :

- `MerlinProjectImportService.importProjectInBackground` (`@concurrent`) exécute la lecture et l'analyse XML ou SQLite hors du MainActor. L'appel est structuré : il hérite de l'annulation de la tâche d'import.
- `Task.checkCancellation()` entre les étapes lecture → analyse → rapprochement, dans la boucle des activités XML et après la requête SQLite principale. Le bouton « Annuler l'import » interrompt donc l'analyse en cours.
- `AppShellView.handleMerlinImport` attend cette fonction ; `store.importMerlinProject` reste appelé sur le MainActor (isolation du store inchangée).

## Environnement

macOS 26.6.2, Apple Silicon, Apple Swift 6.4 (`swiftlang-6.4.0.34.1`), Command Line Tools. Banc local identique à celui de l'[issue #39](2026-11-02-issue-39.md#environnement) : module métier compilé avec `swiftc`, sans l'interface SwiftUI. Fichiers XML générés dans le dossier temporaire. Ce banc ne valide ni la compilation complète de l'application ni son interface.

### Correction et preuve de détection

La réactivité est désormais vérifiée par une sonde synchronisée : à l’entrée du parsing, le worker attend qu’une tâche sur le MainActor lui réponde. Si l’analyse s’exécute par erreur sur le MainActor, celui-ci ne peut pas répondre avant le délai de garde de cinq secondes et le test échoue. La durée et les écarts de scheduling restent mesurés et publiés, sans assimiler le travail d’une autre suite à une régression de l’import. Les vérifications de thread, contenu, parité et annulation restent actives ; aucun test ni check désactivé.

Première compilation du helper : **échouée** (paramètre Mutex noncopyable sans ownership). Corrigé avant validation par une classe Sendable contenant le Mutex. Banc métier corrigé, base `0ca4b3b` avec modifications du fichier MerlinBackgroundImportTests : **réussi**, sortie 0, 34 tests / 7 suites en 1,309 s, commande `python3 tests/run-business-clt.py /tmp/samourai-pass55-probe > /tmp/samourai-pass55-probe.log 2>&1`.

Contre-épreuve : seule copie temporaire du service modifiée, `@concurrent` remplacé par `@MainActor`. **Échec attendu constaté**, binaire sortie 1 : 6 tests / 1 suite, 5 assertions en échec, dont les deux sondes de réactivité et les vérifications de thread. Ainsi, une analyse sur le MainActor est toujours détectée. Le fichier de production n’a pas été muté.
