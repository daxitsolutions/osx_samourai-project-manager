# Validation de l'issue #75 — 2 novembre 2026

## Périmètre

[Issue #75](https://github.com/daxitsolutions/osx_samourai-project-manager/issues/75) : `./package.sh` échoue avec « external macro implementation type 'SwiftUIMacros.StateMacro' could not be found ».

Base : `15887fc` (`main`). Commit testé : `8f85ac6d321451ff95b49815715cd63379853ef2` (branche `codex/fix-75-build-toolchain`). Les compilations ci-dessous ont été lancées avant ce commit, sur des scripts identiques ; seuls `README.md` et le test de scénarios ont été finalisés ensuite.

### Cause

`xcode-select -p` renvoie `/Library/Developer/CommandLineTools`. `swift build` utilise alors cette chaîne, qui ne fournit pas le plugin `SwiftUIMacros` : tous les `@State` et les vues qui en dépendent échouent. Xcode est installé et sa licence a été acceptée, mais il n'est pas la chaîne active. Le code de l'application n'est pas en cause.

### Changements

- `package.sh` et `run.sh` : nouvelle fonction `use_xcode_toolchain`, appelée avant la compilation. Elle agit ainsi :
  - si `DEVELOPER_DIR` est déjà défini, il est respecté ;
  - si Xcode est déjà la chaîne active, rien ne change ;
  - si les Command Line Tools sont actifs, `DEVELOPER_DIR` pointe vers `/Applications/Xcode.app` (ou un autre `Xcode*.app`) pour la durée du script ;
  - si aucun Xcode n'est installé, le script s'arrête avec un message indiquant d'installer Xcode et d'accepter sa licence.
- Le réglage système (`xcode-select`) n'est pas modifié.
- `README.md`, section Prérequis : Xcode est requis ; les Command Line Tools seuls ne suffisent pas.
- `tests/scripts/toolchain-selection.sh` : test des 4 cas, sans compilation.

## Environnement

macOS 26.6.2, Apple Silicon. Xcode 27.2 (27B52), Apple Swift 6.4.2, dans `/Applications/Xcode.app`. Licence acceptée par l'utilisateur. `xcode-select -p` = `/Library/Developer/CommandLineTools`, ce qui est la configuration de l'issue.

- l'appel vient de `AppLocalizer.bundle(for:)`, lui-même appelé depuis `AppShellView.sidebarView`.

### Diagnostic

- **Le binaire installé n'est pas celui de cette branche.** Il est daté du 19 juin 2026 (UUID `0162BACB-4087-32BC-9410-AFFA3241C423`, identique au rapport de plantage). Comme `./package.sh` échouait (cette issue), aucune nouvelle version n'avait été installée.
- **Ce que le vieux binaire cherche :** son accesseur `Bundle.module`, généré par l'ancien SwiftPM, ne cherche le bundle de ressources qu'à la racine du `.app` et dans un chemin absolu de compilation, `<checkout>/.build/arm64-apple-macosx/release/SamouraiProjectManager_SamouraiProjectManagerApp.bundle`.
- **Pourquoi il plante maintenant :** ce dossier de compilation n'existe plus. Or `package.sh` copie le bundle dans `Contents/Resources`, que cet accesseur n'examine pas. D'où le `fatalError`.
- **Le binaire produit par la chaîne Xcode** (`./package.sh --no-install` ci-dessus, UUID `BD0E0889-2386-36E3-86B4-9BF59B4E03B4`) cherche d'abord dans `Bundle.main.resourceURL`, c'est-à-dire `Contents/Resources`. Il ne contient aucun chemin `.build`. Vérifié avec `strings` : 0 occurrence.
